# IDEA（活文档 · 逐轮只增）

## 原始 idea（r001-in，2026-11-16）

> 目前的开发 Agent 底层是谁在干活呢？我们的分工就是 Claude Code，但是目前的开发有了新的明确流程规范，包括后期的运维。但是我们也可以用 VS Code 来做开发管理，所以这个开发工作到底应该在哪里完成交互呢？VS Code 可以通过图形化终端启动 Claude Code 来完成 Vibe coding 开发任务。

## 问题重述（r001 分析后）

不是一个「换工具」问题，而是**交互载体与契约边界**问题，拆成三个子问：

1. **底层确认**：干活引擎 = Claude Code（Agent SDK）+ glm-5.3 模型路由，与载体无关 —— 已澄清（见 r001-out 第一节三层表）。
2. **主交互模式**：开发日常交互主体是 DSH headless 派发、人直接 vibe coding、还是混合（人经 VS Code 介入 debug/review/紧急修复）？→ 决策点 1。
3. **载体与边界**：若引入 VS Code，用集成终端跑 CLI（兼容现状）还是官方 IDE 扩展（待验证）？VS Code 会话是否同样必须持 Change Spec？→ 决策点 2、3。
4. **运维交互面**：后期 ops 是否也进同一载体？→ 决策点 4。
